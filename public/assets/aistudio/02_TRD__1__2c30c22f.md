## 2. Architecture Overview

```
User Browser
    │
    ▼
React + TypeScript (Vite) — SPA
    │
    ├── Supabase Client (via env vars)
    │       ├── Auth (sessions, JWT)
    │       ├── Database (PostgreSQL via RLS)
    │       └── Storage (images)
    │
    └── Stripe Checkout (redirect to Stripe, return to /order-confirmation)

Admin Browser
    │
    ▼
Same React App → /admin/* routes (RLS + role check)
    │
    └── Supabase (admin-level operations via anon key + RLS policies)
```

## 4. Supabase Integration Strategy

### 4.1 Client Setup
```typescript
// src/lib/supabase.ts
import { createClient } from '@supabase/supabase-js'

const supabaseUrl = import.meta.env.VITE_SUPABASE_URL
const supabaseAnonKey = import.meta.env.VITE_SUPABASE_ANON_KEY

export const supabase = createClient(supabaseUrl, supabaseAnonKey)
```

### 4.2 Auth Strategy
- Supabase Auth with email/password
- Session stored in localStorage by Supabase client
- `AuthContext` wraps app with `onAuthStateChange` listener
- `ProtectedRoute` component wraps customer-only pages
- `AdminRoute` component wraps `/admin/*` — checks `profiles.role === 'admin'`
- Admin user is created manually in Supabase Auth + `profiles` table with `role = 'admin'`

### 4.3 Storage Strategy
- Bucket: `product-images` (public read, authenticated write)
- Bucket: `banners` (public read, authenticated write)
- Bucket: `payment-proofs` (private, admin read only)
- Image URLs: Supabase public URL via `supabase.storage.from().getPublicUrl()`
- Max image size: 5MB per file
- Accepted formats: JPG, PNG, WebP

## 6. Security Requirements

1. **RLS enabled on ALL tables** — no table is publicly writable without auth.
2. **Admin role** checked via `profiles.role` column; admin-only operations enforced by RLS policies.
3. **Stripe secret key** NEVER in frontend — Stripe Checkout session created server-side (Supabase Edge Function or via Stripe's client-only Checkout with `publishable key` only).
4. **Supabase service role key** NEVER in frontend or GitHub repo.
5. All env vars use `VITE_` prefix; never hardcoded.
6. Input validation on all forms (client-side + Supabase constraints).
7. Coupon validation happens server-side (Supabase function or RLS).
8. Payment proof uploads are private bucket — only admin can read.

## 7. Payment Integration

### 7.1 Cash on Delivery (COD)
- Customer selects COD → order placed with `payment_method = 'cod'`, `payment_status = 'pending'`
- Admin confirms payment on delivery manually

### 7.2 JazzCash / EasyPaisa (Manual)
- Customer selects → shown account number + instructions
- Customer uploads payment screenshot to `payment-proofs` bucket
- Admin reviews and confirms manually → updates `payment_status = 'confirmed'`

### 7.3 Stripe (Card)
- Frontend uses Stripe.js with `VITE_STRIPE_PUBLISHABLE_KEY`
- Stripe Checkout redirect flow (hosted by Stripe)
- Webhook or return URL updates order `payment_status = 'paid'`
- Stripe secret key stored only in Supabase Edge Function environment

---

## 10. Performance Requirements

- Lazy load all page-level components (`React.lazy` + `Suspense`)
- Images: `loading="lazy"` + WebP preferred
- Product lists: paginated (12/24 per page) or infinite scroll
- TanStack Query for caching: `staleTime: 5 * 60 * 1000`
- Skeleton loaders on all async data
- Debounced search input (300ms)
